1. System Overview

本次改造把 RiskCoordinator 的本批次选择器替换为可配置的集合搜索模式：对一个 role 下所有 risk subgrid 的临时候选 detector 建立候选全集，对候选全集的 power set 进行搜索；每个搜索元素是一个完整 detector 集合 T，评估 elite ∪ T 形成的 ensemble 效果，并按 role 对应的目标和约束选择一个最终集合。

新模式继续由 RiskCoordinator 负责协调，但集合搜索本身由一个新的 RiskSubsetTrainingGrid 承载。该 TrainingGrid 组合现有 GroupBasedGrid，复用 Training 的 sampling、Domain、feedback、checkpoint 生命周期。

本设计不改变以下边界：

  • SubGridRiskOptimized 负责本 subgrid 的 detector / metric 搜索和临时样本产生。
  • RiskCoordinator 负责跨 subgrid、同 role 的批次集合选择。
  • ReversalGrid 负责把选择结果回写到各 subgrid，并继续现有 loop bundle 导出。
  • outer elite_detectors 仍由后续 outer feedback 累积；集合搜索阶段只把 elite 当固定 baseline。

3. Architecture Design

3.1 数据和搜索定义

对一个 role 定义：

  • E：所有参与该 role 的既有 elite detector 集合，固定不变；
  • C：所有同 role risk subgrid 临时候选的并集；
  • T：待选 detector 集合，T ⊆ C；
  • 评估对象：E ∪ T；
  • 搜索空间：P(C)，包括空集和全集。

已存在于 E 的 detector 不再重复作为新的选择变量，但其 signal 仍然进入每个 ensemble 评估。候选成员的 identity 必须是 (subgrid_id, detector_num)，不能只使用 detector_num，因为不同 subgrid 允许出现相同的 detector number。

3.3 为什么复用现有 GroupBasedGrid

本设计将 power set 映射为稳定的 1-based subset rank：

ParameterNode(
    operation_type="combination",
    param_name="members",
    member_space_size=len(candidate_members),
    member_counts=tuple(range(len(candidate_members) + 1)),
)

当前 ParameterNode 的 combination operation 已支持无序、不重复组合；member_counts=0..N 后空间大小为 2**N。ParameterTreeCodec.decode_detector_num(rank) 可将 rank 解码为候选 member index tuple。

随后使用：

  • GroupSearchSpace 管理 [1, 2**N] 的连续 rank 区间；
  • GroupBasedGrid 管理 loop state、sampling 和 feedback；
  • GroupMethodSamplingPolicy 从当前 rank group 取得集合样本；
  • GroupScoreRefineFeedbackPolicy 根据 SCORES 保留并细分高分 rank 区间。

这里的 rank 只属于内部集合搜索 grid。RiskSubsetTrainingGrid 必须负责 rank 与真实 (subgrid_id, detector_num) 的边界转换，防止 rank 被误导出为 detector number。

Power set 的 rank 具有稳定 codec 语义；搜索过程不物化全部集合，只对当前 group 采样的 rank 解码。搜索参数 num_groups、num_top_groups、group_sampling_method 和 max_loop_num 属于集合选择阶段，应与 risk_sampling_inner_* 配置分开。

Power set rank：排序与数值范围显式化补全搜索边界

41 · 原方案

41 使用 combination(member_counts=0..N)，rank 范围为 1..2**N；未给出候选数上限，也未说明 rank 排序。

43 · 独立评估 / 修订说明

43 提醒 triangular 的浮点计算在 N > 53 后存在精度问题，N ≥ 63 的 rank 超出 int64；要求在 Layer A 限制 N。

62 是 42 选择的整数表示上限，不代表消除了 N > 53 时 triangular 采样粒度变粗的限制；42 §7.8 仍明确保留这一说明。

5. Data Architecture

5.1 Role context 的构建

RiskCoordinator 在每个 role 内执行：

  1. 按 (subgrid_id, detector_num) 收集 candidate rows；
  2. 排除已经属于该 subgrid baseline 的候选成员；
  3. 以稳定键排序，分配 member_index；
  4. 合并每个 subgrid 的 selection runtime，使不同 bundle 的局部 detector_id 不被误认为全局 id；
  5. 为每个策略建立 baseline runtime detector id tuple；
  6. 生成 RiskSubsetContext。

candidate_df / baseline_df 的原有 bundle 契约继续保留。跨 subgrid 合并时，逻辑成员 identity 使用 (subgrid_id, detector_num)；signal matrix 的 runtime identity 使用 strategy-specific detector_id 映射。不可依赖不同 selection runtime bundle 的 detector id 恰好全局唯一。

一、当前链路（简述）

  1. 每个 SubGridRiskOptimized.sampling() 先跑内层 risk sampling Training，把留下的 detector 写进 state.sampled_detectors，再把本 subgrid 的候选和 elite 单独导出一个 bundle，跑一次策略管线，得到 last_runtime_bundle（sub_grid_risk_optimized.py:122-153）。
  2. ReversalGrid.sampling() 结束时调用 _prepare_risk_ensemble()（reversal_grid.py:465）。它收集各 bundle，交给 RiskCoordinator。coordinator 按 role 合并信号，返回 selected_by_subgrid，再由 apply_risk_selection() 改写各 subgrid 本轮的 sampled detector。
  3. 外层导出 sampled ∪ elite。Domain 在 ReversalDomainBackend 里按 role 做 OR 聚合，形成真正的 ensemble；之后 outer feedback 决定哪些 detector 进 elite。

二、现有 bug（greedy 模式已受影响）

  • detector_id 跨 subgrid 冲突。每个 subgrid 各自导出 bundle，编号都从 1 开始（export_jsonl.py:176，经 sub_grid_risk_optimized.py:264-273）。_build_risktype_strategy_runtime 按 detector_id 合并信号（risk_coordinator.py:81-88），同 role 两个 subgrid 的信号会互相覆盖。_detector_nums_by_subgrid 用 detector_id.isin（risk_coordinator.py:395）回推时也会串号。

文档 Risk 2 / Risk 3 只针对新模式提到这两点。建议做一个两种模式共用的 role context builder，替换 _build_risktype_bundle。不要保留两条并行的合并路径，否则 greedy 继续带着 bug 跑。

三、需要改的设计点

  1. RiskSubsetContext 放错层（文档第 143 行）。 文档把它放在 para_grid/coordinators/，可它的消费方是 domain/.../compute/risk/ensemble_subset_eval.py，这样 compute 层就反向依赖 para_grid。现有的同类结构 DetectorBundleBySubgrid、RuntimeSignalByStrategy 都在 domain/backends/python/risk_sampling_runtime.py。建议放到 domain 侧，也就是 40 号文档原先写的 risk_subset_runtime.py。顺带一点：risk_coordinator.py:31-35 的 RuntimeSignalByRisktypeStrategy 和 RuntimeSignalByStrategy 完全相同，可以删掉。

  • 失败语义：删掉 _prepare_risk_ensemble 里吞异常、保留全部候选的 except，内部错误直接暴露。N 上限定为 62，配置检查放在边界层。

还有两件事没有验证：finished subgrid 残留旧样本、training_grid.strategy_ids 可能被改写，这两点都只是读代码推断的，没跑测试复现，文档里已列为风险。

建议先合入实施顺序的第 1-3 步。这三步本身就修好了 greedy 模式，可以先跑一次完整实验看看去掉 except 后会冒出什么错误，再接着做子集搜索。
