1. System Overview

本次改造把 RiskCoordinator 的本批次选择器替换为可配置的集合搜索模式：对一个 role 下所有 risk subgrid 的临时候选 detector 建立候选全集，对候选全集的 power set 进行搜索；每个搜索元素是一个完整 detector 集合 T，评估 elite ∪ T 形成的 ensemble 效果，并按 role 对应的目标和约束选择一个最终集合。

新模式继续由 RiskCoordinator 负责协调，但集合搜索本身由一个新的 RiskSubsetTrainingGrid 承载。该 TrainingGrid 组合现有 GroupBasedGrid，复用 Training 的 sampling、Domain、feedback、checkpoint 生命周期。

本设计不改变以下边界：

  • SubGridRiskOptimized 负责本 subgrid 的 detector / metric 搜索和临时样本产生。
  • RiskCoordinator 负责跨 subgrid、同 role 的批次集合选择。
  • ReversalGrid 负责把选择结果回写到各 subgrid，并继续现有 loop bundle 导出。
  • outer elite_detectors 仍由后续 outer feedback 累积；集合搜索阶段只把 elite 当固定 baseline。

2. Current Codebase Status

2.1 当前实际调用链

Training.one_loop()

              -> RiskSamplingDomainBackend

        -> export selection_runtime

  -> ReversalGrid.export_sample_artifacts()
     -> _prepare_risk_ensemble()
        -> collect DetectorBundleBySubgrid
        -> RiskCoordinator.select_current_loop_ensemble()
        -> _apply_risk_selection()

        -> export outer loop bundle

  -> ReversalDomainBackend
     -> detector signals
     -> role ensemble aggregation
     -> outer feedback

SubGridRiskOptimized.sampling() 当前已经在 inner training 后构建 selection runtime。DetectorBundleBySubgrid 包含：

  • candidate_df：本轮可供 coordinator 选择的 detector metrics；
  • baseline_df：该 subgrid 既有 outer elite 的 detector metrics；
  • strategy_runtime_by_id：每个策略的 signal matrix、prepared 数据和 starting equity。

因此集合优化直接消费 selection runtime，不再重新运行 detector pipeline，也不把 inner training 的 athlete 当作跨 subgrid 的 detector identity。

ReversalGrid._apply_risk_selection() 只替换本轮 sampled_detectors，并过滤对应的 sampled_metric_nums_by_detector。它不在 coordinator 阶段修改 elite_detectors。

3. Architecture Design

3.1 数据和搜索定义

对一个 role 定义：

  • E：所有参与该 role 的既有 elite detector 集合，固定不变；
  • C：所有同 role risk subgrid 临时候选的并集；
  • T：待选 detector 集合，T ⊆ C；
  • 评估对象：E ∪ T；
  • 搜索空间：P(C)，包括空集和全集。

已存在于 E 的 detector 不再重复作为新的选择变量，但其 signal 仍然进入每个 ensemble 评估。候选成员的 identity 必须是 (subgrid_id, detector_num)，不能只使用 detector_num，因为不同 subgrid 允许出现相同的 detector number。

3.3 为什么复用现有 GroupBasedGrid

本设计将 power set 映射为稳定的 1-based subset rank：

ParameterNode(
    operation_type="combination",
    param_name="members",
    member_space_size=len(candidate_members),
    member_counts=tuple(range(len(candidate_members) + 1)),
)

当前 ParameterNode 的 combination operation 已支持无序、不重复组合；member_counts=0..N 后空间大小为 2**N。ParameterTreeCodec.decode_detector_num(rank) 可将 rank 解码为候选 member index tuple。

随后使用：

  • GroupSearchSpace 管理 [1, 2**N] 的连续 rank 区间；
  • GroupBasedGrid 管理 loop state、sampling 和 feedback；
  • GroupMethodSamplingPolicy 从当前 rank group 取得集合样本；
  • GroupScoreRefineFeedbackPolicy 根据 SCORES 保留并细分高分 rank 区间。

这里的 rank 只属于内部集合搜索 grid。RiskSubsetTrainingGrid 必须负责 rank 与真实 (subgrid_id, detector_num) 的边界转换，防止 rank 被误导出为 detector number。

Power set 的 rank 具有稳定 codec 语义；搜索过程不物化全部集合，只对当前 group 采样的 rank 解码。搜索参数 num_groups、num_top_groups、group_sampling_method 和 max_loop_num 属于集合选择阶段，应与 risk_sampling_inner_* 配置分开。

4. Core Component Design

4.1 RiskSubsetMember

建议新增于 para_grid/coordinators/risk_subset_context.py：

class RiskSubsetMember:
    member_index: int
    subgrid_id: str
    detector_num: int

职责是定义一个逻辑候选成员的稳定 identity，并提供该成员在每个策略 runtime 中对应的 detector id。一个逻辑成员可能在多个策略 runtime 中有不同的 runtime detector id，但在 power set 中只能占一个 bit / member index。

4.2 RiskSubsetContext

    role: str
    loop_num: int

它组合现有 GroupBasedGrid，而不是复制 group search 算法。主要状态包括：

  • 当前内部 grid 的 subset rank 样本；

  • 当前最佳可行 subset 的 rank 和 metrics。

内部 BaseGridState.sampled_detectors 存放 subset rank，不代表风险 detector。export_sample_artifacts() 只保存集合搜索审计信息和稳定 member identity，不生成新的 detector loop bundle；materialize_samples() 使用固定 runtime，保持 no-op。

5. Data Architecture

5.1 Role context 的构建

RiskCoordinator 在每个 role 内执行：

  1. 按 (subgrid_id, detector_num) 收集 candidate rows；
  2. 排除已经属于该 subgrid baseline 的候选成员；
  3. 以稳定键排序，分配 member_index；
  4. 合并每个 subgrid 的 selection runtime，使不同 bundle 的局部 detector_id 不被误认为全局 id；
  5. 为每个策略建立 baseline runtime detector id tuple；
  6. 生成 RiskSubsetContext。

candidate_df / baseline_df 的原有 bundle 契约继续保留。跨 subgrid 合并时，逻辑成员 identity 使用 (subgrid_id, detector_num)；signal matrix 的 runtime identity 使用 strategy-specific detector_id 映射。不可依赖不同 selection runtime bundle 的 detector id 恰好全局唯一。

5.2 集合评估结果

内部结果最小包含：

athlete
subset_rank
strategy_id
role
objective metric columns
constraint metric columns

每个 subset 在每个 strategy 上先计算完整 elite ∪ subset ensemble，再以现有跨 strategy 聚合口径形成 subset-level objective / constraint。缺少可行 subset 时，由 role-level 选择函数返回明确的无结果状态；不静默把未评估的临时候选当成已选结果。

5.3 存储和 checkpoint

集合 Training 使用独立 result store 和独立 project output：

<outer loop output>/risk_ensemble/<role>/

不能复用外层或 inner risk sampling 的 SCORES、SPLIT_HISTORY，避免不同 grid 的 athlete 含义冲突。完整实验产物仍写入 D:\data\grid-sqx\codex\<experiment>；仓库只保存设计、配置、测试和轻量 artifact pointer。

Training.serialize() 的 checkpoint 必须能够恢复：

  • role；
  • 固定 candidate member 顺序；
  • baseline runtime identity；
  • ParameterTreeCodec 的候选规模；
  • 当前 GroupBasedGrid search space；
  • 已评估 subset metrics。

恢复时不能用另一批候选或另一批策略 runtime 替换原 context。

class RiskCoordinator:

保留现有对外选择结果契约。内部按 role 分发：

  -> 现有选择路径

6.3 ReversalGrid

修改 para_grid/grids/reversal/reversal_grid.py：

  • 保持 _collect_runtime_risk_inputs() 收集真实的 last_runtime_bundle；
  • 在 _prepare_risk_ensemble() 中继续调用 coordinator；
  • 传递 subset search 配置或在 coordinator 初始化时注入；
  • 保持 _apply_risk_selection() 只回写本轮 sampled detector 和其 metric 映射；
  • 保持 outer elite 的更新属于后续 feedback 阶段。

如果某个 subgrid 本轮没有新 candidate，但仍有既有 elite，它必须能作为 baseline-only 来源参与 role context。该场景的 runtime 准备应复用现有 selection runtime builder；不在 coordinator 内重新访问 raw data。

11. Key Decisions and Risks

  • Decision 1：按 mkr_constrain / opr_constrain 分 role 建立独立 power set。→ 与现有 risk metrics、constraints 和 evaluator 输出边界一致。
  • Decision 2：使用 ParameterNode 的 combination operation 表示 power set。→ 复用现有无序组合和 rank/unrank 能力，不新增重复 codec algebra。
  • Decision 3：新建 RiskSubsetTrainingGrid，组合现有 GroupBasedGrid。→ 集合 rank 的语义在新边界封装，现有 group grid 保持单一契约。
  • Decision 4：每个 subset 评估 elite ∪ subset 的真实 ensemble metrics。→ 集合 scoring 直接使用最终评估对象。
  • Decision 5：最终返回一个完整 subset，再按 subgrid 拆解。→ 防止把多个已评分集合错误合并成未评估集合。
  • Decision 6：保留 RiskEnsembleSelection 对外结果契约。→ ReversalGrid 和 SubGridRiskOptimized 只需消费原 detector selection 结构。
  • Risk 1：候选数量增大时 power set rank 空间增长。→ 使用隐式 rank、group sampling、feedback 和 max_loop_num，不物化全部 subset。
  • Risk 2：不同 bundle 的 runtime detector id 可能局部重复。→ 在 role context 构建阶段建立策略级 runtime identity 映射，compute 不负责修复 identity。
  • Risk 3：无新候选的 subgrid 仍有 elite。→ 将 baseline-only runtime 纳入收集契约，不能因没有 last_runtime_bundle 就丢失 baseline。
  • Risk 4：集合搜索的 SCORES 与 inner risk sampling 的 athlete 语义冲突。→ 使用独立 project output 和 result store，subset rank 只在 RiskSubsetTrainingGrid 内解释。
  • Risk 5：配置与实际实现的目标/约束字段不一致。→ 集合 scoring spec 从 RiskEnsemblePolicy 的 role-specific 配置显式生成，不复用 inner risk sampling 的默认 spec。
